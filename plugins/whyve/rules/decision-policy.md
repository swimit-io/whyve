# Decision capture policy

Act only on a user choice signal. Reuse Current bodies already read while nothing changed. Find candidates with metadata `list` (exact filters: scope match, key, keywords, text), then `read` selected bodies. An empty or incomplete page is not proof of absence; never widen automatically to the whole vault.

Judge meaning from actual Decision, Rationale, Rejected alternatives and non-empty Revisit conditions, not IDs, digests or metadata. Proceed quietly when compatible. On a conflict or changed reason, quote those sections before the conclusion and label the revisit condition with exactly one of `satisfied`, `no evidence`, or `ambiguous`. `satisfied` needs facts establishing the stored condition; the requested conflicting action is not evidence.

Hold the affected action: no code, file or command change may advance it before the answer. Ask one explicit binary question. Keep means the action is not performed; supersede permits it only after that explicit choice. A satisfied revisit condition authorizes reassessment, not implementation. The explicit choice settles the decision payload and authorizes recording without a second storage question.

Then propose one mature choice per milestone with scope and key. Do not re-propose dismissed or deferred choices without new evidence. A genuine user choice is required for DEC in every mode; policy authorization is not commitment evidence. Missing rationale or alternatives become quality flags; never invent them.

Follow the shared [recording policy](../skills/context/references/recording-policy.md) for `explicit|auto|adaptive`. Supersede needs `compare`, a `replace` judgment for the predecessor and `separate`/`support` for every other mandatory record, then `prepare` with the receipt and judgments and `apply` in the same response. Use the active language for user text.
