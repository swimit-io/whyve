# Vault protocol (`context-common/v3`)

The packaged core (Node.js 20.20.0+) is the only reader-writer of the vault.
`whyve schema [KIND]` prints the machine-readable model: kinds, headers,
sections, limits.

## Storage

- A vault is an ordinary directory with `context/`; Git is optional.
- Records live in `context/<kind>/`, history in `context/<kind>/retired/`.
  Names are `YYYY-MM-DD-title.md` (DOCUMENT and TERM: `title.md`); a title change
  never renames a file and IDs are never part of the name.
- A record is a header block of `key: <compact JSON>` lines between `---`,
  then `## Section` bodies in kind order, then `## Sources` last
  (`- relation: ref` or `- relation: ref — note`). Host metadata uses namespaced
  headers such as `howse.thread`; `whyve.` is reserved.
- `context/<kind>/<kind>.index.md` has one plain Markdown row per record and is
  regenerated by the core. `whyve refresh --fix` rebuilds indexes from records.

| kind | authority | key and slot | changes |
|---|---|---|---|
| snapshot | staging | none | `update` replaces content; `discard` |
| observation | evidence | none | supplement, `supersede`, `retire invalidated`, `discard` |
| decision | authoritative | required; one Current per scope+key, overlapping scopes need `separate` | supplement, `supersede`, `retire withdrawn` |
| intent | authoritative | required; unique per exact scope+key | supplement, `supersede` |
| document | authoritative | required; unique per exact scope+key | `update` replaces content |
| assumption | provisional | none | supplement, `supersede`, `retire confirmed|refuted` |
| term | definitional | derived from `term`; term, aliases and deprecated terms must not overlap in overlapping scopes | supplement, `supersede`, `retire deprecated` |
| archive | evidence | none | immutable; `discard` only |

Supplement means an update may fill an empty optional section or extend one
(new text starts with the old text). Meaning changes use `supersede`, which
moves the predecessor to history with reciprocal `supersedes` /
`superseded-by` sources. History records are `doNotFollow: true`.

## Discovery

- `list`: index metadata only, exact filters, no ranking: `--kind`,
  `--state current|history|all`, `--scope S --scope-match
  exact|ancestor|descendant|overlap`, `--key`, `--keyword` (repeatable,
  `--keyword-match all|any`), `--id`, `--text` (substring of title or
  summary), `--created-from/--created-to`, `--updated-from/--updated-to`,
  header conditions `--header KEY=VALUE`, `--header-contains`,
  `--header-regex`, `--order recent`, `--limit` (default 50, max 100) and
  `--cursor`. `coverage` reports queried and unqueried kinds and whether the
  page is complete; an empty page only means no row matched those filters.
- `search-headers`: reads header blocks only (`--select howse.*` returns
  values), in pages of at most 500 files.
- `read ID [--section NAME]... [--max-bytes N] [--cursor C] [--raw]`: actual
  sections, sources, quality flags, lifecycle and `contentDigest`. A partial page
  has `complete: false`; continue with `nextCursor` before judging.
- The kind wrappers (`decision_cli.mjs list …`) narrow `list` to their kind.

## Writing

See the [recording policy](recording-policy.md): `prepare` (optionally after
`compare`) then `apply`, with user or policy authorization. Previews are frozen
under the vault for 7 days; apply re-checks every file digest, the project settings and the
registry under the vault lock, writes atomically through a journal and is
idempotent. `runtime recover` restores an interrupted journal after proving the
writer is gone.

## Output and exit codes

One JSON envelope on stdout. Exit 0 success, 2 usage or schema, 3 not found,
5 conflict or approval, 6 integrity, 1 unexpected. A `context-common/v2` vault
is readable; writing requires `whyve migrate-project PATH --to-format
context-common/v3` (see MIGRATION).
